## Translation Example

The framework decouples legacy syntax from the target implementation, allowing the `PythonEmitter` and `ORMEmitter` to generate clean, idiomatic code that is structurally distinct from the original Natural program.

**Legacy Input (`RATECALC.nsp`):**
```natural
/* Freight Calculation Sample
DEFINE DATA
PARAMETER USING TARIFF-P
LOCAL
  1 #BASE-CHARGE (P9.2)
  1 #SURCHARGE (P7.2)
END-DEFINE

FIND (1) TARIFF-VIEW WITH CLASS = #SHIP-CLASS
  #BASE-CHARGE := RATE * #SHIP-WEIGHT
  IF #SHIP-WEIGHT > WEIGHT-LIMIT
    #SURCHARGE := HEAVY-SURCHARGE
    ESCAPE BOTTOM
  END-IF
END-FIND
END
```

**Generated Python Output (`ratecalc.py`):**
```python
from dataclasses import dataclass
from decimal import Decimal
from target_orm import Tariff

@dataclass
class RatecalcContext:
    ship_class: str
    route_zone: str
    ship_weight: Decimal
    final_charge: Decimal
    base_charge: Decimal = Decimal('0')
    surcharge: Decimal = Decimal('0')

def execute_ratecalc(ctx: RatecalcContext, session):
    for record in session.query(Tariff).filter((record.class_ == ctx.ship_class)):
        ctx.base_charge = (record.rate * ctx.ship_weight)
        if (ctx.ship_weight > record.weight_limit):
            ctx.surcharge = record.heavy_surcharge
            break
    return ctx
```

## What this is

A deterministic compilation framework designed to migrate decades-old Software AG Natural business logic to modern Python and SQLAlchemy architectures.

Instead of a fragile "regex and replace" transpiler, this framework parses Natural into a strict Semantic Intermediate Representation (IR), decoupling legacy syntax from modern domain modeling. It features a topological DAG build system, Git-style diff output, and a Human-in-the-Loop AI remediation engine for graceful syntax fallbacks.

## Core Architecture

This framework implements a 5-layer migration strategy:

1. **Deterministic Frontend:** A robust `lark` EBNF grammar parses legacy Natural code, constructing an initial Abstract Syntax Tree (IR0). It dynamically resolves dependencies across the workspace (e.g., `DDM` and `NSA` files).
2. **Semantic Normalization:** A lowering pass converts Natural-specific idioms into a canonical Pydantic object model (IR1). Implicit parameter scopes become explicit dataclass state; Adabas `FIND` loops become generalized `query_iteration` concepts.
3. **AI-Assisted Interpretation:** When deterministic parsing fails on undocumented legacy macros, the compiler halts and generates a rich, schema-bound prompt. This allows an LLM (Human-in-the-Loop) to synthesize the missing AST node against strict Pydantic rules without hallucinating.
4. **Target Generation:** Distinct code emitters translate the semantic IR into modern stacks:
* `PythonEmitter`: Generates pure Python business logic using `@dataclass` state contexts.
* `ORMEmitter`: Translates Adabas `.ddm` views into fully typed SQLAlchemy declarative models.


5. **Differential Verification:** The orchestrator maintains in-memory state and performs Git-style unified diffs against the local filesystem before writing, ensuring complete transparency for behavioral equivalence testing.

## Features

* **Topological Dependency Sorting:** Automatically analyzes `INCLUDE` and `USING` statements to build a DAG, ensuring files compile strictly after their dependencies.
* **Smart Change Detection & Diffing:** Compares generated output against physical files to prevent unnecessary disk writes, emitting colored `-` and `+` diffs via `rich`.
* **Garbage Collection:** Automatically unlinks obsolete build artifacts from the `build/` directory if they are no longer generated by the source files.
* **Strict Typing:** All Intermediate Representations use highly strict `pydantic` schemas (`SerializeAsAny`), guaranteeing complete data serialization for downstream tools.

## CLI Usage

The framework exposes a Typer-based command line interface:

### 1. Build a Workspace

Scans an entire directory of Natural files, calculates the dependency graph, and strictly orders the compilation. Emits IR0 (Raw AST), IR1 (Semantic), and Python/SQLAlchemy targets.

```bash
natural build path/to/workspace

```

**With Diff Output:**
Show exact Git-style diffs of what the compiler will change before it writes to disk.

```bash
natural build path/to/workspace --diff

```

### 2. Parse a Single File (Debugging)

Useful for targeting a specific file and debugging the Semantic Lowering Pass.

```bash
# Output the raw YAML Semantic IR
natural parse path/to/RATECALC.nsp -I path/to/workspace

# Output the generated Python business logic
natural parse path/to/RATECALC.nsp -I path/to/workspace --emit-python

# Output the generated SQLAlchemy ORM
natural parse path/to/RATECALC.nsp -I path/to/workspace --emit-orm

```

## AI Remediation (Human-in-the-Loop)

Legacy Natural environments often contain custom macros or 30-year-old syntax quirks. If the `lark` parser encounters an unexpected token, the compiler will purposefully crash and output an **AI Remediation Prompt**.

This prompt isolates the exact line, column, and failing context. It dynamically embeds your current `natural.lark` grammar and `models.py` schema. Simply copy the terminal output and paste it into ChatGPT, Claude, or Gemini to receive a deterministic grammar fix.

```text

├── cli.py                    # Typer orchestration, diffing, and garbage collection
├── codegen/
│   ├── orm_emitter.py        # Adabas DDM to SQLAlchemy generator

├── grammar/
│   └── natural.lark          # EBNF Grammar for Software AG Natural
├── ir/
│   ├── models.py             # Pydantic schemas representing IR1 logic
│   ├── semantic.py           # Base symbol table and semantic operations
│   └── serializer.py         # Custom clean YAML serialization
└── normalizer/
    ├── ast_visitor.py        # Lark Tree to IR0 Transformer
    ├── lowering.py           # Semantic Lowering Pass (IR0 -> IR1)
    ├── parser.py             # Exception handling and Prompt Generation
    └── workspace.py          # Lazy dependency loading for DDMs and NSAs

```

### 5. Semantic Lowering Pass (`lowering.py`)

* **Logical Operator Mapping:** Added support for `"AND"` and `"OR"` binary operators.
